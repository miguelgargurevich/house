# Contrato de API (backend nuevo)

Lo implementa la rama `feat/backend-seguro`. El frontend se construye contra esto.
Autenticación: `Authorization: Bearer <token>` (lo pone `api()` de `src/api.ts`). Errores: `{ error: 'mensaje' }` con el status HTTP.
Login: `POST /api/auth/login` {email,password} → {token,user}; `GET /api/auth/me` → usuario.
Montos (`Decimal`) llegan como string: usa `soles()` / `Number()`.

- Todas las listas devuelven `{items, total, page, pageSize}` con query `?page=1&pageSize=20&q=texto&orden=campo:asc|desc` (pageSize máx 100; `q` busca en nombre/código/email/descripcion según recurso). Recursos: usuarios, empresas, complejos, pisos, estructuras, unidades, conceptos, recibos, pagos, tareas, auditoria. Los GET por id devuelven el objeto. POST→201 con el objeto creado; PUT/PATCH→objeto actualizado; DELETE→204.
- Rutas CRUD (mismos nombres de hoy): /api/usuarios, /api/empresas, /api/complejos, /api/pisos, /api/estructuras, /api/unidades, /api/conceptos, /api/recibos, /api/pagos, /api/recibo-conceptos, /api/recibo-concepto-unidades; NUEVA /api/tareas (TareaMantenimiento) con `PATCH /api/tareas/:id/estado` {estado: pendiente|en_progreso|completada}. Las listas de unidades incluyen `propietario:{id,nombre}`, `inquilino:{id,nombre}`, `complejo:{id,nombre}`; las de recibos incluyen `complejo`, `totales:{monto, cobrado, pendiente}` (calculados) y `estado`; las de usuarios incluyen `empresa:{id,nombre}`.
- Inquilino↔unidad: añade `inquilino_id Int?` a Unidad (relación "InquilinoUnidad" con Usuario) y actualiza el seed para asignar cada inquilino a una unidad distinta de las de su complejo. Tras cambiar el esquema ejecuta `npx prisma db push` contra la base local y vuelve a sembrar con una BD vacía (para eso crea una BD nueva `house_dev2` en el mismo Postgres o usa el esquema por defecto; NO uses `prisma migrate reset` ni `db push --force-reset` sobre la base `house` principal).
- Perfil: `PUT /api/me` {nombre, telefono}; `PUT /api/me/password` {actual, nueva} (verifica la actual, mínimo 8).
- Residentes: `GET /api/me/unidades` (propietario: sus unidades; inquilino: la suya) con complejo; `GET /api/me/cargos?estado=pendiente|pagado|vencido&page=` → cargos (ReciboConceptoUnidad) de SUS unidades con `{id, monto, estado_pago, estado (pagado|pendiente|vencido, calculado por fecha_vencimiento del recibo), concepto:{nombre}, recibo:{id,mes,anio,descripcion,fecha_vencimiento}, unidad:{id,codigo}, pagos:[…]}`; `GET /api/me/cargos/:id`; `GET /api/me/pagos` (pagos de sus cargos); `POST /api/me/cargos/:id/pagos` {metodo_pago: transferencia|yape|plin|efectivo|tarjeta, referencia?, observaciones?} registra un Pago por el monto del cargo, marca estado_pago='pagado' y fecha_pago, rechaza si ya está pagado o no es suyo (404).
- `GET /api/dashboard/resumen` según rol. admin/superadmin: `{recibos_emitidos, cargos_pendientes_monto, cobrado_mes, morosos (unidades con cargos vencidos), unidades_total, tareas_abiertas, cobrado_por_mes:[{mes:'2026-05', emitido, cobrado} (últimos 6)], estados:{pagado,pendiente,vencido}}` (superadmin: global + `empresas_total`, `usuarios_total`; admin: su empresa). propietario/inquilino: `{deuda_total, vencidos, proximo_vencimiento:{cargo_id,monto,fecha}|null, pagado_ano}`. mantenimiento: `{tareas_pendientes, en_progreso, completadas}`. seguridad: `{unidades_complejo, complejo}`.
- `GET /api/reportes/morosidad` (admin/superadmin): lista de unidades con deuda vencida: `[{unidad, propietario, deuda_total, cargos_vencidos, dias_max_atraso}]`, paginada igual que las demás.
